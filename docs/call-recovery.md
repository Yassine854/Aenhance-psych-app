# Consultation connection recovery

Deploy the frontend build and updated Node signaling server together, then restart the signaling process. Existing open pages need refreshing before testing. This change has not been verified against the production proxy or on two real devices.

Unexpected WebSocket closures reconnect with fresh room authorization, backing off from one second to fifteen seconds. Active media stays connected during signaling recovery. The server retains presence for thirty seconds and suppresses departure notifications when a replacement socket joins. After that grace period, a signaling-only departure does not close media that is still connected. Explicit hangup still sends an immediate departure.

Disconnected, failed or stalled media connections attempt recovery every five seconds while signaling is available. A pending local offer gets fifteen seconds for its answer before it can be rolled back. Authorization rejections and duplicate-tab replacement (close code 4001) stop signaling retries. Hangup cancels recovery timers. Network outages and server failures can still interrupt media; recovery cannot guarantee continuous connectivity.

Camera capture prefers 720p at 24 fps, with caps of 720p and 30 fps. Video sender bitrate is capped at 1.2 Mbps; this is a ceiling rather than a target or minimum, so browser congestion control can reduce it further. Audio capture requests echo cancellation, noise suppression, automatic gain and mono input as preferences. Browsers/devices can ignore unsupported preferences. Unsupported sender controls are nonfatal. These use standard [WebRTC sender controls](https://www.w3.org/TR/webrtc/).

Signaling messages are processed in order so asynchronous offers finish before their following ICE candidates. Concurrent local offer creation is blocked. Joining without a camera reserves a video sender for enabling it later; streamless remote tracks are also supported. Returning to the visible tab or regaining internet connectivity triggers recovery when needed. Event listeners are removed on hangup, including when leaving during startup.

Token and TURN requests time out after ten seconds; stalled WebSocket joins retry after fifteen seconds. Expiring TURN credentials are refreshed within five minutes of expiration, with a thirty-second retry cooldown. After successful periodic refresh, the psychologist initiates an ICE restart to renew the route. Existing relay configuration is kept if the credential endpoint is unavailable. Long-call renewal still needs verification against the deployed Coturn server.

Validation: `node --test tests/call-recovery.test.js tests/call-media.test.js signaling/server.test.js signaling/auth.test.js tests/consultation-request.test.js` and `npm run build`.

Deployment check: with two devices in a call, briefly block only the signaling WebSocket and restore it. Audio/video should remain active, and chat should work again after rejoining. Separately interrupt the network briefly to check media recovery. Verify that intentional hangup leaves immediately and opening a duplicate tab does not create a reconnect loop. Correlate any recurring abnormal close codes with proxy and Node logs; this change does not identify or repair their underlying infrastructure cause.

Room authorization failures now get one retry with a newly fetched token, then stop. Code 1008 identifies invalid room authorization; code 4008 identifies a missing/timed-out room join; code 4029 identifies the message rate limit. Older servers using 1008 for timeouts/rate limits are recognized by their known close reasons. A fresh five-minute token permits up to thirty seconds of Node clock lag; expired tokens remain rejected. Node logs only the rejection category (`signature_mismatch`, `expired_token`, `clock_skew`, `malformed_token`, or `invalid_claims`), never tokens, names or secrets. The WebSocket URL now comes from `config('signaling.url')` so Laravel configuration caching preserves it. Refresh Laravel's config cache and restart Node after changing environment settings.

Also test Chrome/Edge, Firefox, Safari/iOS and Android; both join orders; camera off at join then on; Wi-Fi/cellular changes; low bandwidth and packet loss; leaving while permissions or credentials are pending; and calls exceeding the TURN lifetime. Capture connection time, selected candidate type, RTT, packet loss and bitrate from browser WebRTC diagnostics. Local mocked tests and a successful bundle build cannot establish real media quality or uptime. Review deployed TURN reachability, relay capacity, proxy timeouts and process supervision before claiming production reliability. The current default TURN URLs use UDP/TCP on 3478; restricted networks may need a separately provisioned and verified TURN/TLS service on 443. No production infrastructure was changed.
